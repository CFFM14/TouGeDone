# 天下人苦头歌久矣 · TouGeDone

<img src="icons/icon128.png" width="72" height="72" alt="扩展图标">

面向头歌（EduCoder）的 Edge 扩展，集成选择题助手、DeepSeek 编程题助手和混合模式。当前版本 **2.9.5（AI 输出容错修复版）**，默认混合模式。

## 安装

1. 打开 [最新正式版](https://github.com/CFFM14/TouGeDone/releases/latest)，下载 `TouGeDone-v版本号.zip`，解压到固定目录。
2. 在 Edge 打开 `edge://extensions`，开启“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的目录。
4. 打开头歌答题页，点击扩展图标打开助手。

更新时覆盖原加载目录，在扩展页点击“重新加载”，再刷新答题页。沿用同一扩展时，已保存的密钥可继续使用。

## 使用

- **混合模式（默认）/编程题助手**：先点面板右下角“设置”，填写并保存 DeepSeek API Key，返回答题页后点击“开始”。
- **选择题助手**：无需配置密钥，选择模式后点击“开始”。
- 勾选“通过后自动下一关”后，只有明确通过才继续；不同模式按其范围处理或跳过题型。
- 拖动标题栏移动面板；同一标签页跨关记住位置。高级选项可调整主题、配色、布局和尝试参数。
- “停止”结束后续尝试并处理当前结果；“关闭”立即移除面板并终止后续自动操作。已发给平台的请求仍可能完成。

## 功能

- 单选逐题尝试；多选先清洗锁定，再进行最多4题的并行排除和命中拆分。
- 多选候选差量切换，共同选项不重复点击，已确认正确题锁定。
- 编程结合题干、已有源文件、公开评测反馈分析并修改允许的文件；模板只填指定区域。
- 自动保存确认、评测、失败反馈修复和冷却等待，模型固定为 `deepseek-flash`。
- AI 返回格式或内容未通过检查时，反馈具体原因并额外补试两次（每轮最多3次），通过整批校验后才写入；已知失败点见《使用说明》末尾。
- 主面板与设置页统一外观，默认使用流程简化为“设置 → 保存 → 开始”。
- 主面板“高级选项与外观 → 主题”新增少女心、赛博朋克、古风古韵，自动记住选择。

API Key 在扩展设置中填写，保存在本机扩展存储，不随仓库发布；编程时相关题干、代码和公开反馈会发送给 DeepSeek，调用消耗账户余额。

## GitHub 更新

从 **2.9.1** 起支持授权目录后的一键更新：

1. 在面板右下角点击“更新”（也可以从“设置”进入版本与更新）。
2. 首次点击“选择插件目录”，选中 Edge 当前加载的原文件夹，允许读写。
3. 以后点击“一键更新”，插件会检查、下载、校验、备份、覆盖并重新加载；完成后刷新答题页。

浏览器可能再次询问目录权限。任务运行时先停止；更新期间保持设置页打开。写入失败会恢复原文件，中途关闭导致中断时，下次进入设置点击“恢复更新前文件”。需要新增权限的版本使用 ZIP 手动安装并经浏览器确认。不会在后台无人操作时替换插件。

**2.9.0 及更早版本需先手动升级一次到 2.9.1**：下载 ZIP 覆盖原加载目录，在 `edge://extensions` 重新加载，再刷新答题页。不要卸载原扩展，原密钥保留。首次目录授权必须由使用者在浏览器中完成。

主检查接口限流、超时或服务错误时，自动改读本仓库最新 Release 附件中的更新信息。两条路径都失败时明确提示，不误报最新版。

更新只使用本仓库正式 Release；不使用 DeepSeek 密钥。校验 GitHub 附件 SHA-256、逐文件摘要和固定文件名单，拒绝选错目录、非法路径或权限扩大。源码保存在本地后交给浏览器重新加载，不从远程地址注入脚本。

## 维护者发布新版

需要Node.js（测试）和Python 3（打包发布）。现有GitHub Git凭据需具有本仓库写权限，凭据仅在发布进程内存中使用，不写入包或日志。

1. 修改代码及版本记录，同步提高 `manifest.json` 和 `package.json` 的版本号。
2. 执行 `npm test`，然后提交并推送 `main`。
3. 执行 `npm run release`。脚本仅在工作区干净且HEAD与远程main一致时发布。

发布命令会生成白名单安装包、SHA-256文件、一键更新数据包和对应正式GitHub Release。同版本旧附件不覆盖，已有标签指向其他提交时停止；不要用相同版本替换已发布代码。只有推送代码而没有发布Release，插件不会将其视为新版。`npm run pack` 只在本地生成安装包。


## 版本号约定

采用 `主版本.功能版本.修复版本`：整体重构等大更新升第一位（1.0.0 → 2.0.0）；新增功能升第二位（1.0.0 → 1.1.0）；只有小 bug 修复升第三位（1.0.0 → 1.0.1）。前一位升级时，后面的位数归零。同次发布包含多种变化时按最高级别升级；用户明确指定版本号时以指定为准。已发布的历史版本保留，不追溯改名。
